# tunnelhop

Runs work through a local [tunnelhop](https://github.com/NoelisTired/tunnelhop)
stack (gluetun + rotator). Only traffic sent through the proxy uses the VPN exit
IP; the host keeps its own connection.

**The stack must not stay running.** Start it for the task, stop it when done.

## Flow

1. **Start:** `node ~/.claude/skills/tunnelhop/scripts/tunnelhop.mjs up`
   Starts Docker Desktop if needed (macOS), waits until the tunnel has an exit
   IP, and arms an auto-stop after 30 idle minutes as a safety net
   (`--ttl <min>`, `0` = off).
2. **Work:** run every request through `run`, which injects the proxy env:
   ```bash
   node ~/.claude/skills/tunnelhop/scripts/tunnelhop.mjs run -- curl -s https://api.ipify.org
   node ~/.claude/skills/tunnelhop/scripts/tunnelhop.mjs run -- python3 scrape.py
   ```
   The child process gets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` (+ lowercase),
   `NODE_USE_ENV_PROXY=1`, and `ROTATOR_URL` + `ROTATOR_API_KEY` so a script can
   rotate itself (`POST $ROTATOR_URL/rotate` with header `X-API-Key`).
   Each `run` re-arms the auto-stop timer.
3. **New IP** when asked, or when the target blocks/rate-limits (403/429/captcha):
   `... tunnelhop.mjs rotate`. Takes ~5 to 40 s; requests during it fail.
4. **Stop, always,** also when the task failed: `... tunnelhop.mjs down`

One-shot alternative: `... tunnelhop.mjs with -- <cmd>` does up, run, down.

Other commands: `status`, `ip`. Full list: `--help`.

## Rules

- **Never print or echo the proxy password or API keys**, and never read the
  project's `.env` directly. The helper injects them; refer to the proxy as
  `http://127.0.0.1:8888` in chat.
- Every request that should use the VPN must go through `run` (or a tool that
  honours the proxy env vars). Tools that ignore `HTTP_PROXY` (e.g. a built-in
  web fetch tool, browser automation) do **not** use the proxy; say so.
- `curl`, `wget`, Python `urllib`/`requests`/`httpx` honour the env vars.
  **Node's built-in `fetch` does NOT on Node < 24** (it silently goes direct).
  In Node scripts use `undici`'s `setGlobalDispatcher(new EnvHttpProxyAgent())`,
  or shell out to curl. For Playwright, pass
  `proxy={"server": "http://127.0.0.1:8888", "username": ..., "password": ...}`
  built from `HTTPS_PROXY` inside the script.
- Before scraping, verify the exit IP **with the same tool/runtime the scraper
  uses** and compare with `ip`, so you know traffic really leaves via the VPN.
  If it fails, stop: the kill switch blocks traffic rather than leaking the
  user's own IP, so a failure means "tunnel down", not "fall back to direct".
- Respect the target site's terms and rate limits, and the VPN provider's terms.
- If `up` fails: check `docker compose logs gluetun` in `~/tunnelhop`
  (an expired or revoked WireGuard key is the usual cause).

## Config

Credentials live in `~/tunnelhop/.env` (generated by its `setup.sh`).
`TUNNELHOP_DIR` overrides the project location.

## Helper

`~/.claude/skills/tunnelhop/scripts/tunnelhop.mjs`, run with `--help` for the command list.
